# 存储池领域纵切面规格

日期：2026-10-15。承接 workflow-foundation，不迁移旧业务实现。

## 范围与验收标准

1. PoolManager 管生命周期、路由、普通盘唯一归属；Pool 装配通用协调者和三个独立领域宿主。
2. 强类型 ID，领域对象不保存 Future/Workflow phase，只有所属领域能提交其变化。
3. 节点连通不等于加载；旧观测不覆盖新事实，断连撤销加载资格。
4. 硬盘上线是一个完整 Workflow：读取节点、Add/确认成员、Open、启用 IO 并确认 Up；
   Add/Open 只是步骤。离线和一个镜像 BG 的卷创建各有具名 Workflow。
5. 卷布局限定同 Tier、2/3 个不同节点；创建前校验容量/资格；初始化成功才标 Valid。
6. 分配确认先于 BG 引用；重复/并发创建不能双分配；失败保留空间而不盲目释放。
7. 离线保守失效，重新上线不自动恢复数据有效性；未知外部/提交结果阻塞后继修改。
8. 元数据确认前查询只见旧内存；取消等待实际操作停稳，不提前交接对象。
9. Pool 协调服务实现纯冲突策略：重复拒绝、离线取消上线、事实版本替换、其余对象准入。
   拒绝/Busy 不取消旧工作；实际交接必须停稳。不同 Pool 独立、普通物理盘唯一归属。
10. 显式外部接口、内存适配器、完整示例、失败/并发测试；基础库和根工程回归通过。
11. Workflow 决策读取也是只读 Activity；外部观察才用 Query，不混用执行路径。
12. 手动暂停在安全边界确认，不强停 IO；恢复同一 Run，保留对象占用；取消可唤醒暂停。
    Signal 缓存、Timer 截止时间、资源等待撤回和终态竞态均有明确语义及测试。

## 实现摘要

独立 storage-pool crate，仅通过 path 依赖新 workflow-foundation。业务注册固定领域
服务，PoolHandle 封装受约束入口，PoolWorkflowCoordinator 实现应用策略，领域声明
Activity 资源，由基础库执行。具名异步流程
拥有跨领域步骤顺序，不拥有领域状态。领域校验与字段级提交在各服务内，外部 IO 通过
注入端口；默认适配器仅模拟。存量源码、未提交实验文件不纳入本次提交。

## 非目标与需后续确认

真实 SDB/user_dp、自动放置、EC、完整 VD 类型、节点移除、磁盘缩容/重建、释放 BLK、
全局优先级/硬抢占、跨主恢复与持久工作流均不在本次范围。offline 的保守失效策略是本轮
验证应用编排的明确选择，不能直接当作全部物理 DOWN 或计划维护业务的最终规格。

## 目录分层

应用编排与 Pool 装配位于 `src/app/`；实体和状态所有者按领域归入
`src/domain/{disk,node,vd}/`，外部端口留在领域层；模拟适配器位于
`src/infrastructure/`。基础库保持业务无关，现有公开根路径兼容保留。

## 离线编排骨架

应用流程追加 `VdCommand::WaitRebuild` 和 `DiskCommand::Remove` 两个领域步骤。
当前只有占位错误，既不声称完成重建，也不提交成员移除；等待重建失败时不会进入
移除步骤。测试验证盘已 Down、数据已 Invalid，但成员及已分配空间保留。

## 协调者管理节点与磁盘流程的交接

新增 NodeTransitionRequest、节点上下线 Workflow、应用路由登记和节点转换冲突策略。
业务目标用同一节点单调观测序列排序，Workflow 只调用领域 Activity；协调者发取消并
通过现有许可机制等待旧流程/Activity 停稳。领域新增批量 IO、批量失效与重建等待边界，
不实现真实重建和移除。路由登记覆盖在途 Add，防止节点下线遗漏刚加入的磁盘。

测试覆盖重建期间上线、单纯连接事实取消下线、盘上线/盘离线/节点离线接连到达、在途
首次 Add、旧序号拒绝、重建不明阻塞上线、批量回复身份异常和逐盘部分提交。
当前仍为保守完整集合准入；通用批量部分准入、索引式局部唤醒留待基础库扩展。

## 配置化规则与任务观测收敛

`app/coordination/rules.rs` 提供有名称、按顺序匹配的类型化 PoolRules/RulePolicy；
PoolManager 在创建 Pool 前通过 with_rules 配置，或通过 with_policy 注入普通 Rust 策略。
规则表保留旧节点序号保护，基础库统一保证准入容量、完整决定后取消、占用和停稳。
运行期策略热更新与外部配置文件解析不在本次范围。

基础库在接受提交时建立独立任务索引。PoolHandle 提供按 ID 的查询、只读订阅和暂停/
恢复/取消。快照记录命中的准入规则、流程对象、状态、请求标志和显式进度；准入解释
不是实时阻塞图。普通终态历史有界，不确定终态保留，丢弃 Run 不丢失执行控制。
观测进度不是领域真相，非法上报被忽略，不改变业务结果。订阅合并更新，无持久日志。
